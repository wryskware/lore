# Chunking, Ranking, Embeddings

Detail design for the M1 slice. Drafted by agent from research patterns; not ratified — treat specifics as [!working] unless a decision cites them.

## Chunk identity

> [!working] Content-addressed, not counter-based
> Chunk IDs derive from (path, span-anchor, content hash) — re-parsing an unchanged file yields identical IDs, so vectors and FTS rows survive. The CodeGraph counter-churn failure ([[../7_Research/raw/D_codegraph]]) is the anti-pattern. All stores update in one SQLite transaction per generation (D-0004 storage model).

## Chunking by file class

| Class | Strategy |
|---|---|
| Code (tree-sitter grammar available; C# flagship) | Symbol-level nodes with leading comments/attributes attached; merge tiny siblings, split oversized with overlap (opencode pattern). No call extraction (D-0005). |
| Markdown | Heading-tree leaves carrying `heading_path` provenance (CodeGraph pattern). Frontmatter parsed: `design_status`, `decision_refs`, D-NNNN references in body recorded as chunk metadata. |
| UXML / USS | First-class text chunking (element/rule-block granularity where cheap, else windows). |
| Serialized Unity YAML (`.unity`, `.prefab`, `.asset`) | Experimental (M2): size-capped, dumb windows, per-project excludable. GUIDs indexed as plain text. |
| Unknown text | Line windows with overlap. Binary: skipped. |

## Embedding text construction

Chunk text is prefixed with a compact header — language, relative path, symbol kind/name or `heading_path` — before embedding (opencode's technique; measurably helps code retrieval). Query and document encodings honor the model's instruction prefixes ([[../7_Research/raw/C_embeddings]] implications section).

## Embedding provider config

```toml
[embeddings]
endpoint = "http://127.0.0.1:8080/v1"   # OpenAI-compatible; llama-server default
model = "jina-code-embeddings-1.5b"
dimensions = 1536
query_prefix = ""                        # model-card instruction strings
document_prefix = ""
batch_max_items = 64
api_key = ""                             # optional; sent as Bearer if set (llama-server may want a dummy)
```

Persisted per-index fingerprint: model id + revision + dims + prefixes + normalization (`model_id_tag`, CodeGraph pattern). Fingerprint mismatch ⇒ explicit re-embed, never silent vector mixing. Endpoint absent ⇒ lexical-only search with a visible `status` warning (D-0007).

## Ranking

1. FTS5 BM25 (full chunk text — bodies, not just names; the CodeGraph names-only mistake) and vector cosine run in parallel; fuse with RRF.
2. Vault-status modifier after fusion, per [[../2_Memory/2.1_Memory_Model]]: `decided`/ledger-cited > `leaning` > exploration/unclassified > `deprecated`/scratch. Ordering is the requirement; weights are tuning.
3. Session-ledger chunks (M3) get a recency term and an authority cap below vault material.
4. Result payload: ranked chunks with provenance + status labels; `expand` fetches surroundings so `search` stays token-lean.

> [!open] Whether `search` should interleave code and vault-doc results by default or group by corpus; decide from dogfooding.
