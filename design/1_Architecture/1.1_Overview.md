# Lore Architecture Overview

## Topology

> [!accepted] D-0007
> One daemon, one owner. Thin clients proxy; nothing else touches index state.

```text
Claude Code ─┐
Codex        ─┤  lore-mcp (thin stdio proxy)
other agents ─┘        │
                       ▼
        versioned loopback HTTP (axum)   ◄── lore CLI
                       │
              ┌────────┴────────┐
              │   lore daemon   │
              │  registration   │
              │  watcher+debounce
              │  index scheduler│
              │  search/ranking │
              │  session ledger │  (tier 2 memory, see [[../2_Memory/2.1_Memory_Model]])
              └────────┬────────┘
              ┌────────┴────────┐
              │  SearchStore    │  seam: v0.1 SQLite; Tantivy+arroy upgrade path
              │  (FTS + vectors │
              │   + metadata)   │
              └────────┬────────┘
                       │
     OpenAI-compatible /v1/embeddings endpoint (external; llama-server on RTX 5090)
```

## Subsystem inventory

| Subsystem | v0.1 | Notes |
|---|---|---|
| Daemon lifecycle, single-instance, registration | ✓ | heartbeat + atomic write-then-rename handshake (CodeGraph pattern); admission discipline (codebase-memory pattern) |
| Watcher + debounce + coalescing | ✓ | notify 8.x + debouncer-full; distinguish own writes; rescan on overflow |
| Markdown + code chunking | ✓ | tree-sitter for code; heading-tree chunking with `heading_path` provenance for Markdown; `design_status`/D-NNNN awareness (D-0004) |
| Hybrid search (BM25/FTS + vectors + fusion) | ✓ | status-aware ranking for vault docs |
| Embeddings | ✓ external endpoint only | `model_id_tag` persisted with vectors; re-index on model change |
| Session ledger | later milestone | D-0006 tier 2 |
| Graph | never (D-0005) | codebase-memory-mcp optional sidecar |
| Roslyn/SCIP C# semantics | possible future | gated on demonstrated need |
| Daemon-managed llama-server | later convenience | D-0007 |

## Storage

> [!working] SearchStore seam
> v0.1: everything in SQLite — metadata, FTS5 lexical, vectors (sqlite-vec or brute-force cosine; corpora are ~10⁵ chunks). One transaction domain makes index-generation atomicity trivial.

> [!candidate] Tantivy 0.26 + arroy 0.8
> The planned upgrade engine behind the same seam if FTS5 ranking quality or vector scale disappoints in practice. Wrysk leans toward this being the eventually-right engine ("seems like the right choice, but … can be a later development"). Measure before switching; see risk list in [[../7_Research/raw/E_rust-stack]].

## Reference patterns (evidence: [[../7_Research/01_landscape]], raw reports)

Copy: codesearch serve-hub/thin-client split, repo lifecycle states, Windows file-lock discipline, worktree HEAD polling · opencode lease/publication protocol, comment-aware chunking, context packs, pluggable embedding endpoint · CodeGraph heartbeat handshake, EmbedMode tri-state debounce, Markdown heading-tree chunking, golden-file MCP harness, `model_id_tag` · agent-memory-mcp untrusted-by-default provenance.

Avoid: per-process watchers/locks (CCE), counter-based IDs + RAM-graph snapshots (CodeGraph), fixed algorithmic embeddings (codebase-memory), names-only BM25, tree-sitter call graphs (D-0005).
