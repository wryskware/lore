- **M4 — Earned upgrades.** Only as measurement demands: Tantivy+arroy SearchStore swap ([[../1_Architecture/1.1_Overview|candidate]]), daemon-managed llama-server, Roslyn/SCIP C# helper, named-pipe transport.

## Indexing scope note (round 2, Q4)

Code + Markdown + text-like Unity formats (**UXML, USS** — Wrysk's actual ask) are first-class in v0.1. Serialized YAML (`.unity`/`.prefab`/`.asset`) is experimental: size-capped, dumb-chunked, easy per-project exclude; GUID-as-searchable-text is the cheap win to evaluate.

## Backlog (tracked as GitHub issues on wryskware/lore)

- README + license choice (before the repo is ever public).
- **Semantic search over issue tracking** — index GitHub Issues into the same search surface (Wrysk, 2026-08-14). Needs expansion into a real spec (sync model, comment threading, closed-issue ranking, provenance links back to issue URLs); roadmap-level for now, likely post-M3. Rationale: issue tracking belongs in the tracker for a typical repo workflow, unlike the Lexomancy keep-it-in-the-vault approach — but its content is exactly the kind of context agents keep rediscovering.
- Linux: WSL2 smoke test around e2e-benchmark time (M1/M2 boundary). Rust makes compatibility low-risk; no multi-platform CI until it earns its keep.
- **Go + C/C++ symbol-aware chunking** (Wrysk, 2026-08-14; re-pointed by D-0023, 2026-08-17) — now three declarative chunker plugins rather than in-tree additions: each is a grammar `.wasm` plus a manifest, no core work. The C++ MSVC build-weight concern dissolves — a wasm grammar costs core nothing. Until someone authors them these files index via the unknown-text line-window fallback. In-tree set stays C#/Rust/Python/JS/TS/Markdown, marked for migration onto the plugin contract (issue #25).

## Benchmark posture (D-0009)

E2e tasks on the fixture repos with retrieval on/off, same model, same task: tool calls, tokens, wall time, task success. Luna-free measures capability only — pair with a cost-bearing model before making any token-savings claim.
