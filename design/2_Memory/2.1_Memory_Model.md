# Memory Model — Two Tiers

> [!accepted] D-0006
> Tier 1: durable knowledge is repo-resident, human-readable Markdown (the vault). The DB is a derived, rebuildable index — never the home of a memory. No separate MCP write API for durable memories; agents write files, and canon flows only through the promotion gate.
> Tier 2: a session/thread ledger of heavily-compacted execution summaries — working memory for developer and agents, not canon.

## Tier 1 — Lore docs (the vault)

- Source of truth: Markdown with `design_status` frontmatter, certainty callouts, and D-NNNN ledger references (Lexomancy conventions, D-0001).
- Lore's job is *awareness*, not storage: parse status/refs at index time; rank by them at query time.

> [!working] Status-aware ranking
> At comparable similarity, `decided`/ledger-cited material outranks `leaning`, which outranks `exploration`/unclassified, which outranks `deprecated`/`99_Scratch`. A hard-boundary decision should never be buried under a semantically-similar scratch note. Exact weighting is an implementation detail to tune; the *ordering* is the requirement.

> [!working] Promotion = vault diff
> When an agent believes something deserves durability, the output is a proposed file edit / ledger draft for Wrysk's review (the agent-memory-mcp lesson: provenance defaults to untrusted; promotion is gated) — never a DB flag flip.

## Tier 2 — Session ledger

Purpose (Wrysk, planning round 1): point back to the thread where something happened; answer "where'd we leave off", "what's left", "did we do this already"; give agents broader working memory when needed.

- Content: short, heavily-compacted session summaries — ideally posted by the agent itself before signing off, rather than mined from transcripts after the fact.
- Indexed like everything else; recallable by search.
- Not canon. Never outranks vault material on authority; useful for recency and continuity.

> [!accepted] D-0008
> Home: daemon data dir, as Markdown files (one per session), indexed. Capture: agent sign-off summary via `session_log`, with a Stop-hook safety net for forgetful agents. No transcript mining. Location noted as a default that real-user feedback may revisit.

> [!open] Compaction policy and retention (how short is "heavily compacted"; when do old sessions age out of the index) undecided.

> [!open] Whether routing memories ("word evaluation starts in A; multiplier resolution in B") are tier 1 files, tier 2 entries, or both depending on maturity.
