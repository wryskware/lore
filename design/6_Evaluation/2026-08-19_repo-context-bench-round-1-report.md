# RepoContextBench round 1 — lore on someone else's frozen task set

Follows [[2026-08-18_bench-report-format]] where it applies. This is a
*different program* from the e2e rounds it was written for: the task set,
scoring rubric and grader are external, there is no pass-B retrieval grading,
and `pack.py` / `verdicts.json` do not exist here. Sections that cannot be
filled honestly say so rather than being dropped, per that document's principle
3. Numbering restarts at round 1 because this is the first round of a new
program; it is not e2e round 6.

## Headline

- **Efficiency reproduces across all three answerers.** Total tokens fall 29% /
  53% / 66%; wall clock falls 16% / 32% / 55%; tool calls fall 20% / 28% / 72%.
- **Quality does not.** Judge quality moves −3% / +2% / +10%; only the Sonnet
  figure exceeds the measured noise floor, and even that is not significant at
  n=20 (p=0.118).
- **The answerer noise floor is ±0.025 on required-claim recall**, measured by
  running Gemini's off arm twice under identical conditions. Two of the three
  quality results sit inside it and mean nothing.
- **The Sonnet gain is a tail effect, not a lift.** Nine of 20 tasks moved <0.10;
  the mean is carried by four cells that were failing outright off-arm.
- **On Sonnet, lore displaced a strategy rather than trimming one.** The off arm
  spawned 316 subagent messages; the on arm spawned zero, in all 20 cells
  (p=0.004).

## Cell ledger

Generated by `round_report.py`; full 118-row output lives beside the round
JSONLs and is reproduced in the appendix rather than inline, because at three
answerers this table is 120 rows and the format's ~13-column rule is about
width, not length. Cell identity here is `<label>/<arm>/<task>`, which maps to
`~/bench/sandbox/out{,-oc,-cc}/<arm>/<task>/`.

**Deviation from the format, stated explicitly:** this program has no
`bench/results/<stamp>-<cell>/` directory per cell. Artefacts live under the
sandbox output directories and are overwritten by the next round with the same
answerer — the Gemini round A streams were destroyed by round B, and the luna
T02 streams by a Sonnet smoke test. This is the single worst provenance defect
in the round and is carried forward as the first item in § Next.

**The two score metrics are not interchangeable.** `required-claim recall` is a
weighted count against the benchmark's own fixed list of critical/required gold
claims — the judge only decides whether a named claim is present, so the metric
is anchored to an external rubric and is the only figure comparable to
CodeAlive's published numbers. `judge quality score` is the judge's holistic
0-1 opinion. Measured stability differs accordingly: on repeats of a single
answer, quality spread up to 0.17 (σ≈0.09) and flipped the certification gate on
2 of 3 tasks. Recall leads; quality is carried because it catches what a claim
list cannot (hedging, citation discipline, an answer complete but useless).

The certification gate is reported and **never** headlined, for the same reason.

## What this round says

**The efficiency result is real and it replicates.** Three answerers, three
harnesses, three model families, same direction on every metric, with p≤0.02 on
tokens for all three. This is the defensible claim: lore makes an agent
materially cheaper and faster on a task set we did not write, on a repo we did
not choose.

**The quality result is one unreplicated round.** Only Sonnet clears the noise
floor, and it does not clear significance. "lore improves answer quality on
RepoContextBench" is not yet supportable; "lore does not appear to *cost*
quality" is supportable across all three.

### The Sonnet mechanism

The distribution matters more than the mean. Every cell where the off arm
spawned subagents is a large token win (-49.7% to -85.6%, no exceptions); every
cell where it did not is a coin flip, and all six regressions have zero
subagents and none exceeds +22.3%. Off-arm Claude Code answers "I cannot find
this" by fanning out Task agents, each re-reading a large cached prefix — hence
1.15M mean cache-read tokens. Given lore it simply searches.

The same shape appears in the scores: nine of 20 tasks moved <0.10 on recall,
and the mean is carried by four cells that were failing badly off-arm — T14
(0.00→0.86), T15 (0.29→0.57), T17 (0.21→0.50), T08 (0.60→0.80), all `block` or
adjacent. Removing T14 alone drops the mean delta from +0.076 to ≈+0.033, back
near the floor. Against that, T12 lost 0.42 recall, the largest single adverse
move in the round.

The honest reading: **lore did not make good answers better; it rescued answers
that had failed to locate the relevant code at all.** That is a narrower claim
than the mean suggests and a more useful one, because it predicts where the
benefit should appear.

### Steering, and why the arms are not symmetric

The on arm's prompt carries three extra lines: that lore exists, that its
results are pointers to be verified, and that its paths are repo-relative. This
is a disclosed asymmetry, not an accident. An unsteered on-arm pilot showed the
agent never reaching for the MCP server at all (0 lore calls, 70 file-tool
calls), which would have measured nothing. CodeAlive steer their own
`codealive_skill` arm the same way while leaving their standard arm unsteered.
The third line was added after Gemini round A, which is why round A is not
comparable to round B on the on arm.

### Contamination

The benchmark's gold answers are public on GitHub, and a provider-side web tool
executes outside our network namespace where the egress broker cannot see it.
All three answerers therefore had web tools removed at the tool layer, not
merely denied: Gemini via a `PreToolUse` hook (verified to survive
`--dangerously-skip-permissions`, which `permissions.deny` does not), opencode
via `tools` + `permission` both set false, Claude Code via `--disallowed-tools`
plus a hook. Verified by probe on each answerer; 0 attempts across 120 cells.

Host-side leakage was checked for the Claude Code answerer specifically, since
the operator's own `CLAUDE.md` contains delegation instructions that would have
biased the subagent finding: no `CLAUDE.md`, no user skills, no user agents and
no host settings reached the jail (0 of 40 streams mention any of them). The
subagent fan-out is stock behaviour. The corpus's own `AGENTS.md` files appear
in tool *results* in 9 off-arm and 4 on-arm cells — a consequence of the arms
scanning differently, not an injected instruction.

## Harness changes made during this round

Uncommitted; no SHAs. None invalidates a cell in this round except where noted.

- `run_answerer.py` — added the repo-relative path rule to the on-arm prompt.
  **Invalidates the Gemini round A on arm** for comparison against round B.
- `run-sandboxed.sh` / `inner.sh` — added a `claude` agent branch (own HOME,
  credential-only copy, `--strict-mcp-config` arm separation) and made the
  opencode provider block and egress host key off `SBX_OC_MODEL`. The openai
  branch is byte-identical, so the luna round remains comparable.
- `run-claude.sh`, `hookdeny-claude.py`, `run_answerer_claude.py` — new answerer.
- `recount_claude_tokens.py` — **corrects a reporting error made during this
  round.** The original extractor took usage from the terminal `result` event,
  which omits subagent tokens; since subagents were almost exclusively an
  off-arm behaviour, the error ran one way and inverted the sign of the token
  and cache-write results. Corrected figures are used throughout; the original
  extractor is left in place so both are inspectable.
- `score_round.py`, `round_report.py` — batch judge with on-disk verdict cache,
  and the generator for the mechanical sections here.

## Carried over and next

**Carried over** — nothing; this is the program's first round.

**Next**, ordered:

1. **Per-cell artefact directories.** Sandbox output is overwritten by the next
   round with the same answerer; two rounds' raw streams are already lost. Until
   cells are written to `<stamp>-<label>-<arm>-<task>/`, no figure here is
   walkable back to its artefact, which fails the format's principle 2.
2. **Retrieval grading.** No pass-B equivalent exists, so nothing measures
   whether what lore returned was relevant — only that it was called.
3. **Repeat the Sonnet round.** It is the only arm with a signal above the noise
   floor, and n=1. Two more rounds would settle whether +0.076 survives.
4. **A non-Anthropic judge on the Sonnet round.** Sonnet 5 currently grades
   Sonnet 5's own answers; the one cross-judge probe run in this program spread
   0.68 / 0.86 / 1.00 on a single answer.
5. **Investigate T12** (-0.42 recall) and **T14** (+0.86), the two cells that
   determine the Sonnet result.
6. **`cache_write` for the other two answerers**, which neither harness
   currently emits — it bills at 1.25x input and is invisible in their totals.
