# E2E round 5 — Lexomancy on Qwen3.8-27B

A third model over the same ten Lexomancy cells, after luna `high`
([[2026-08-17_e2e-round-3-lexomancy]], corrected) and luna `max`
([[2026-08-17_e2e-round-4-lunamax]]). Same prompts, pins, index, corpus and
harness.

Model: `Qwen/Qwen3.8-27B-FP8` at effort `medium`, served by vLLM on a RunPod
endpoint, 262k context. Two cells concurrent. Graded by luna `max` under
[[2026-08-17_grading-protocol]] — the same grader as round 4, so those two
rounds share a scale; round 3 does not.

**Token counts are not comparable to luna's `input` column.** vLLM reports the
whole prompt as `prompt_tokens` every turn, so this column is the analogue of

(`vllm:prefix_cache_hits_total` / `queries_total` = 86%); it is simply not
reported through the OpenAI-compatible `usage` payload, which is why
`cache_read` is 0 in every cell here.

Across three models and thirty cells, **the on arm has never scored higher than
the off arm on this task set.** Two rounds tie, one loses. That is now the
program's most robust finding and it is not the one lore's design material
assumes.

The cost direction is equally consistent: **-27% (max), -37% (qwen)**, with the
-86% on T3 the largest single-cell effect yet measured.

## T1: the round's one clear on-arm loss

The on arm made 11 lore calls, spent **5.3x** the off arm's tokens, and scored
0.5 to the off arm's 1. Pass B calls the retrieval "uneven" — it returned the
composer, director, simulator and targeting files but missed the live
damage-handler links, so the agent grepped for the rest anyway and paid for
both.

Its four `file:line` citations are **imprecise rather than wrong**: every file
exists and every line is in range, but they land on `/// <summary>` openers or
a blank line rather than the member being cited. The grader called them
`fabricated_citations`, which is the wrong label for what they are, and the
distinction matters because "the on arm fabricates citations" is a much more
serious claim than "the on arm cites a few lines high."

## The first `relevant-but-ignored` cell

Pass B on T3 returns the verdict three previous rounds never produced: lore
returned concrete game-code entry points, **the agent opened none of them**,
and rebuilt the inventory with grep. This is the failure mode Wrysk proposed in
round 2 — "yeah um you're not helping me" — and it took a third model to
produce one instance.

It still scored 1, and at -86% tokens, so the ignored hits cost nothing here.
But the mechanism now has an example, where before it had none.

Uptake overall is much lower than the luna rounds: **16 searches, 97 unique
paths, 11 used (11%), 8 cited (8%)** — against 32%/21% for luna `max` and
22%/15% for luna `high`. This model searches more and uses less of what it gets
back.

## Two errors found in the frozen key

Both surfaced by spot-checking a single grader flag, neither by systematic
audit:

- **`0_MASTER_INDEX.md`** (round 5, T3). The key names a file that does not
  exist; the file is `00_MASTER_INDEX.md`. The agent cited it correctly and was
  marked down for it.
- **`ScalePayloads` at `BattleSimulator.cs:414`** (round 3, T1). The definition
  is at `:1190` and the nearest call site is `:403`. An answer citing `:1190`
  was flagged as a fabrication.

**The key has never been audited.** It is the document every score in this
program is measured against, and two of the first two flags checked against it
were the key's fault rather than the agent's.

## What this round says about the bench

- **Per-cell variance is large.** A smoke-test cell and the matrix cell ran the
  identical off-arm T2: 65,978 input / 5 tools / 31s versus 151,831 / 14 /
  109s. **2.3x on tokens, 2.8x on tool calls, same everything.** Every per-task
  cost figure in every round is n=1 and should be read with that spread in
  mind. Round totals, averaged over five tasks, are steadier.
- **`time_compacting` has never recorded anything.** All 127 cells to date
  store the literal string `'None'` — the harness captures Python's printed
  `None` as text. Compaction has therefore never been measured in any round.
- **vLLM cache metrics need `/metrics` scraping**, and per-arm attribution
  needs the off and on waves run as separate batches (concurrency within a wave
  is fine, since every cell in it shares an arm).

## Next

1. **Audit the key.** Two errors in two checks. Every citation in it should be
   resolved against the pinned checkouts before another round is graded.
2. **Repeat cells.** At least the cheap tasks, so per-task cost has an error
   bar instead of a single sample.
3. **The containment assertion and per-cell timeout** carried over from
   [[2026-08-17_e2e-round-4-lunamax]], both still unbuilt.
4. **Face the consistent result.** Thirty cells, three models: retrieval has
   never improved a score on this task set and reliably cuts cost by a third.
   Either the task set cannot detect the benefit the design material claims, or
   the claim is about cost and should say so.
